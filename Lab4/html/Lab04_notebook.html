Observed order of each rule

Errors are collected in a plain loop, then the standard fitting tool reports the observed order. One representative log log plot is shown.

Iex = exp(1) - 1;
Ns = [8 16 32 64 128]';
rules = {'midpoint', 'trapz', 'simpson'};
for k = 1:3
    rule = rules{k};
    errs = zeros(size(Ns));
    for j = 1:numel(Ns)
        [t, w] = em.quad.nodes(0, 1, Ns(j), rule);
        errs(j) = abs(sum(exp(t) .* w) - Iex);
    end
    p = em.test.convergence(@(N) errs(Ns == N), Ns, struct('plot', strcmp(rule,'simpson')));
    fprintf('%-9s observed order p = %.2f\n', rule, p);
end

The Gauss rule does not fit the same mold

for N = [2 4 8 16]
    [t, w] = em.quad.nodes(0, 1, N, 'gauss');
    fprintf('gauss N = %2d   error = %.3e\n', N, abs(sum(exp(t) .* w) - Iex));
end
% TODO two to four sentences. The three fitted orders above are clean
% power laws and the Gauss errors are not. Explain what convergence
% faster than any power of N means and why a straight line fit is the
% wrong model for it.


% The Gauss quadrature is exact for polynomials up to degree 2N - 1, so its
% error falls faster than any fixed power of N for a smooth integrand (such
% as e^(t)), which means it decreases more rapidly than 1/N^(p) for any
% fixed p. Because of this mismatch, the Gauss errors do not follow a
% power law relationship, and fitting a straight line to the data gives an
% appoximate slope, which is not a good method to measure its convergence.

Finite line against the infinite line formula

d = 1;
Lod = logspace(0, 2, 15)';
ratio = zeros(size(Lod));
for k = 1:numel(Lod)
    L = Lod(k) * d;
    lineC = @(t)[zeros(size(t)) zeros(size(t)) t];
    sl = em.src.lineCharge(1e-9, lineC, [-L/2 L/2], 800);
    Ef = em.field.E(sl, [d 0 0]);
    ratio(k) = Ef(1) / (1e-9 / (2*pi*e0*d));
end
figure; semilogx(Lod, ratio, 'o-'); grid on
xlabel('L / d'); ylabel('E finite over E infinite')
title('Finite line approaching the infinite line')
iAbove = find(ratio > 0.99, 1);
fprintf('ratio first exceeds 0.99 at L/d about %.1f\n', Lod(iAbove));

TODO three to six sentences. The convergence order was measured, not assumed. State one situation later in the course where a wrong observed order will be the first visible symptom of a bug.

% Comparing the observed convergence order against the theoretical order is
% a reliable method to catch bugs in the code. For example, a second order
% method that measures as first order almost always has a boundary handled
% incorrectly, or an off-by-one in the node placement. This will be
% important in the next few labs, especially when dealing with weights and
% electromagnetic surfaces.
